# Binette エディタ（`binette-editor`）

クライアントからビネットを作り、編集し、消せる埋め込みアプリです。EbinaStation v2 の第一弾のアプリで、Station に**同梱**しています（リポジトリの `apps/binette-editor/`）。

> [!WARNING]
> 下書きです。

Station とアプリのあいだの決まり（中継、`Ebina-User` などのヘッダー、子プロセスの起動）は [../spec.md](../spec.md)、`app.json` は [../app-json.md](../app-json.md) を参照してください。

## フォルダ

```
apps/binette-editor/          # リポジトリ（同梱。Station は読むだけ）
├── app.json
├── main.ts                   # entry。API とプレビューを返す
├── names.ts                  # 名前の規則
├── store.ts                  # 保存（一時ファイル → rename、空フォルダの片付け）
└── panoplie/                 # 一覧・編集の画面
    ├── index.bina            # 一覧
    ├── edit.bina             # 編集
    └── files/
        ├── list.js           # 一覧の画面（mount）
        ├── edit.js           # 編集の画面（mount）
        └── editor.css        # 見た目

project/data/apps/binette-editor/
└── binette/                  # 作ったビネット（<名前>.bina）
```

`app.json`:

```json
{
  "label": "Binette エディタ",
  "version": "0.1.0",
  "description": "ビネットを作り、編集し、プレビューする",
  "icon": "📝",
  "entry": "main.ts"
}
```

- 同梱のアプリは、リポジトリの `apps/` から読み込みます（[../spec.md](../spec.md) の「埋め込みアプリ」）。データフォルダは使用者のアプリと同じ `project/data/apps/binette-editor/` で、ビネットを書くのはここだけです。
- 使用者が `project/apps/binette-editor/` を置くと、そちらが使われ、同梱のものは使われません（ログに 1 行出ます）。`EBINA_PROJECT_DIR` がリポジトリの根で `project/apps/` と同梱の `apps/` が同じ実体のときは、同梱の走査を省き、二重に読みません。
- `main.ts` が使う依存は `@binette/core` と `@std/path` だけです（Station の `deno.json` の `imports` にあるもの。子プロセスは `--frozen --cached-only` で動くため、足すときは [../app-json.md](../app-json.md) の手順に従います）。
- 子プロセスの権限は [../app-json.md](../app-json.md) のとおりで、読めるのは `apps/binette-editor/` とデータフォルダ、書けるのはデータフォルダだけです。

## 扱うビネット

- 保存先は `<データフォルダ>/binette/<名前>.bina`（`project/data/apps/binette-editor/binette/<名前>.bina`）です。この中だけを扱います。
- ユーザーは区別しません。ログインできる人は全員、すべてのビネットを読み書きできます。
- ビネットは使用者の画面で再生されます（`js` の asset は、見る人のブラウザで、その人のセッションで動きます）。作れる人は信頼している人に限ってください。

### 名前の規則

名前は `/` で区切れます。`a/b` は `binette/a/b.bina` です。パスにも URL にも、変換せずそのまま使えるよう、次の規則にします。

- 区切りは 1〜64 文字で、使える文字は `A-Z a-z 0-9 . _ -` だけです。
- 区切りが空（先頭・末尾の `/`、`//`）、`.`、`..` は使えません。`\`、空白、日本語などの文字、`%`、`?`、`#` も使えません。
- 全体は 200 文字までです。
- 区切りの末尾を `.bina` にはできません（`a.bina`、`a.bina/b` など）。拡張子は保存のときに付けるため、`a.bina.bina` になってしまうことと、フォルダ `a.bina/` がファイル `a.bina` とぶつかることを避けるためです。
- 名前の大文字と小文字は区別します（`A` と `a` は別のビネットです。大文字小文字を区別しないファイルシステムでは、ぶつかることがあります）。

### 保存と検査

- 保存するときに `@binette/core` の `parseBinette` で形式を検査し、正しくなければ保存しません（400）。
- 本文は UTF-8 で 1 MiB までです。超えたら 413 を返します（ET の本文の上限も 1 MiB なので、クライアントから 413 まで届くことはほとんどありません）。
- 保存は、同じフォルダの一時ファイルに書いてから `rename` で置き換えます。途中で止まっても、古いビネットは壊れません。
- 保存と削除は、アプリの中で 1 つずつ（順番に）行います。同じフォルダでの保存と削除が重なっても壊れず、同じ新しい名前を同時に作ったときに「作れた」（201）になるのは 1 つだけです。
- ビネットは 1000 件までです。上限のときに新しい名前で作ろうとすると 409 を返します（既にあるビネットの上書きはできます）。一覧の応答が中継の本文の上限（1 MiB）に収まるようにするためです（名前は最大 200 文字なので、1000 件でも約 200 KB です）。
- 保存した JSON 文字列をそのまま持ち（整形し直さない）、そのまま返します。
- 削除で、空になったフォルダを `binette/` の手前まで片付けます（`binette/` 自体は残します）。
- 一覧は名前順（文字コード順）です。形式に合わないファイル、`.bina` で終わらないファイル、シンボリックリンクは一覧に出しません。

## 画面

画面のパスは Scene のパスです。画面の `.bina` と `js` は `panoplie/` から配ります（`main.ts` は画面のパスに 404 を返し、Station が `panoplie/` から探します）。

| パス | 内容 |
| --- | --- |
| `/binette-editor` | 一覧。新規作成、編集・プレビュー・削除のボタン |
| `/binette-editor/edit?name=<名前>` | JSON の編集と保存。検査のエラーを表示する。プレビューと一覧へのボタン |
| `/binette-editor/preview/<名前>` | 保存したビネットをそのまま再生する（`main.ts` が `/preview/<名前>.bina` で返す） |

- 画面の `.bina` は、`js` の asset（`src: "/binette-editor/files/list.js"`、`edit.js`）と `css` の asset（`editor.css`）を持ちます。`js` は `export function mount(el, sh)` を持ち、API は `sh.fetch("/binette-editor/api/…")` で呼び、移動は `sh.navigate(…)` です。後始末の関数を返します。
- `js` は画面ごとに 1 ファイルです（相対 import は使えないため、小さな補助は 2 つのファイルに同じものを持ちます）。DOM API だけで作り、ユーザーの値を `innerHTML` に入れません。
- 一覧の画面:
  - 新規作成は、名前を入れて「作成」を押します。名前の規則に合わなければ、その場でエラーを出します。すでにある名前は作れません（作る PUT に `If-None-Match: *` を付けるので、一覧を開いたあとに同じ名前が作られていても上書きしません。サーバーの 412 の「すでにあります」を表示します）。作れたら、ひな形（`entry` が html の asset 1 つ）を保存し、編集画面へ移ります。
  - 削除は、行の中で「削除しますか？」と確かめてから行います。
- 編集の画面:
  - 名前は URL の `?name=`（`location.search`）から読みます。正しくない名前は、エラーと「一覧へ」だけを出します。
  - 保存は「保存」か Ctrl / Cmd + S です。検査のエラーは画面にそのまま出します（保存はされません）。
  - 未保存の変更があるあいだは、ページを離れる前にブラウザの確認（`beforeunload`）が出ます。保存に成功すると、「保存して移る」などの確認の表示は隠れます。
  - 変更があると「未保存の変更があります」と出ます。保存していない変更があるまま「プレビュー」や「一覧へ」を押すと、「保存して移る」「保存せずに移る」「戻る」を確かめます。変更が無ければ、そのまま移ります。
- プレビューの応答（`/preview/<名前>.bina`）は、ビネットの `settings` を除いて返します（JSON として読み、消して直列化し直します。読めないときはそのまま返します）。Scene は取得したビネットの `settings` を覚えて設定画面に出し続けるため、下書きが設定画面に紛れ込まないようにするためです。ほかは保存した内容のままです。
- プレビューは Scene が再生するので、`redirect` のビネットは転送先へ移ります。無いビネットは「見つかりません」になります。
- ボタンには `aria-label` を付け、タップ領域は 44px 以上です。375px 幅で崩れません。文言は日本語です。色は文字色から作るので（`currentColor`、`color-mix`）、明るいテーマでも暗いテーマでも読めます。

## API

クライアントからは `/binette-editor/…` で呼びます（Station がアプリ名を取り除いて渡します）。

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/binettes` | 名前の一覧 `{ "names": ["a", "a/b"] }`（名前順） |
| `GET /api/binettes/<名前>` | 保存した JSON 文字列をそのまま返す（`application/json`） |
| `PUT /api/binettes/<名前>` | 作成・上書き。本文はビネットの JSON。作ったら 201、上書きなら 200。どちらも `{ "name": "<名前>" }`。`If-None-Match: *` を付けると、既にあるときは上書きせず 412。新しく作るときに 1000 件あれば 409 |
| `DELETE /api/binettes/<名前>` | 削除。`{ "name": "<名前>" }` |
| `GET /preview/<名前>.bina` | 保存したビネットを、`settings` を除いて返す（プレビュー用。`HEAD` も可） |

エラーの本文は `{ "error": "<日本語のメッセージ>" }` です。

| ステータス | いつ |
| --- | --- |
| 400 | 名前が正しくない、本文が UTF-8 でない・JSON でない・形式の検査に通らない |
| 404 | そのビネットが無い。プレビューは、名前が正しくないときも 404 |
| 405 | 使えないメソッド（`Allow` ヘッダーを付ける） |
| 409 | 新しく作るときに、ビネットが 1000 件ある |
| 412 | `If-None-Match: *` を付けた PUT で、そのビネットが既にある（「すでにあります」） |
| 413 | 本文が 1 MiB を超えた |
| 500 | 保存先に書けないなど、アプリの内部のエラー（詳細は標準エラーにだけ出す） |

画面の `.bina`・`js`・`css` のパス（`/index.bina`、`/edit.bina`、`/files/…`）は `main.ts` が 404 を返し、Station が `panoplie/` から配ります。
